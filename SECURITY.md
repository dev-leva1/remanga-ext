# Security policy / Безопасность

## Поддерживаемые версии

Проверяйте проблемы на актуальной опубликованной версии и, по возможности, на текущем `main`. Архивные релизы сохранены для истории; отдельные ветки поддержки и гарантированные сроки исправлений не заявлены.

## Как сообщить об уязвимости

Не создавайте публичный Issue с деталями уязвимости, токенами или персональными данными.

1. Если на GitHub доступна функция **Report a vulnerability**, используйте [Security Advisories](https://github.com/dev-leva1/remanga-ext/security/advisories).
2. Если она недоступна, воспользуйтесь [Telegram-ботом обратной связи](https://t.me/remanga_extension_bot) и попросите безопасный способ передачи подробностей сопровождающему. Не отправляйте рабочие секреты даже в приватном сообщении.

Приложите версию userscript/коммит, затронутый компонент, условия воспроизведения, ожидаемое и фактическое поведение, оценку влияния. Используйте обезличенные данные и собственную тестовую среду.

Проект не гарантирует срок ответа. Просим согласовать публичное раскрытие до публикации эксплуатационных деталей.

## Границы безопасности

Userscript действует в контексте авторизованного аккаунта ReManga. См. [данные и разрешения](docs/PRIVACY.md). Соблюдайте ограничения сайта и не проверяйте уязвимости на чужих аккаунтах или данных.

For security reports in English, use the same private reporting channels.
