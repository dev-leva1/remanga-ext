# Участие в разработке

Спасибо за интерес к Remanga Enhanced. Обсуждать задачи можно на русском или английском.

## Перед изменениями

- Проверьте [Issues](https://github.com/dev-leva1/remanga-ext/issues) и [Roadmap](docs/ROADMAP.md), чтобы не дублировать работу.
- Для крупных изменений API, автоматизации, хранения данных или архитектуры сначала согласуйте подход в Issue.
- Уязвимости направляйте по [SECURITY.md](SECURITY.md).

## Рабочий процесс

1. Создайте fork и отдельную ветку от `main`.
2. Установите зависимости через `npm ci` (для бота — отдельно в `feedback-bot/`).
3. Внесите небольшие, связанные изменения в исходники. Не редактируйте собранный userscript вручную.
4. Для изменения userscript выполните `npm run lint`, `npm run build`, `node --check dist/remanga-extension.user.js` и ручную проверку по [Developer Guide](docs/DEVELOPER_GUIDE.md).
5. Откройте PR с описанием поведения до/после, связанным Issue и результатами проверок. Отметьте проверки, которые не запускались.

## Правила

- Не добавляйте токены, cookies, реальные пароли, данные пользователей или локальные конфиги.
- Соблюдайте rate limiting, проверку входных данных и cleanup при SPA-навигации.
- Не добавляйте функции для обхода ограничений платформы, спама или скрытого сбора данных.
- Не обновляйте версию без согласования выпуска; следуйте [release guide](docs/RELEASE.md).
- Новые зависимости и сторонние файлы должны иметь понятное происхождение и совместимые лицензии.

Участники должны соблюдать [кодекс поведения](CODE_OF_CONDUCT.md). Предлагайте только изменения, на которые у вас есть права и которые могут распространяться на условиях [лицензии проекта](LICENSE).
